# Rollback / cleanup gate

No live deployment was performed, so no robot rollback or service restoration
was needed for software delivery. Before any approved deployment record current
release/config/map hashes, owner inventory and exact recovery target privately.

If a session fails, retain ownership until its exact child/subscriptions/native
writer are settled. Use owned session stop; do not kill another camera container,
remove a live lock/socket, restart every service, or delete user maps. Failed
cleanup stays ERROR/CLEANUP_REQUIRED. A broker survives dashboard client loss;
inspect its owned session and process before any recovery. SIGTERM attempts exact
owned cleanup and keeps reservation if settlement fails. Investigate orphaned
socket/process state; do not automatically overwrite it.

Within a separately approved recovery window, stop the owned session, confirm
no producer/writer remains, then disable the optional broker socket config and
restore the recorded deployment/config. Revert additive source through normal
Git history if required; never reset user changes or rewrite published history.
Keep native packages, legacy catalog, original maps, bags and experiment assets.
Hand camera back only to the agreed owner; another task may have taken ownership.
Do not automatically restore ARM/lease/goal or restart a previously released relay.
Record service/PID/owner/map hashes and remaining blockers after cleanup.
