# 조건부 위치 가설 및 화면 변경: 독립 오프라인 검토

검토한 범위에서 추가로 확인된 차단 결함은 없다. 이 판정은 아래 고정 후보의 코드 읽기와 제한된 합성 확인에 한정된다. 통합 snapshot의 전체 검사 결과는 별도 기록하며, 실제 센서·로봇·지도 정확도·정지 상태·Nav2 동작·배포 가능성을 증명하지 않는다.

## 검토한 경계

- 조건부 위치 가설은 고정 backend의 기존 전체 SE(3) 중복 기준과 대표 순서를 검증하고, 원본 후보와 모호성 판정을 보존한다. 그룹의 모든 회원을 prior와 비교하며, 확인 시 같은 신선한 odometry 표본으로 각 회원의 현재 범위를 재검사한다. 원래 기준 안에서도 회원의 높이·기울기 차이가 남을 수 있으며, 하나의 retained 그룹은 전역 유일성이나 실제 정확도를 뜻하지 않는다.
- 그룹 proof UI는 원본 후보 수와 가설 수를 구분하고 회원·현재 진단, source/session·신선도 및 명시적 확인 조건을 검사한다. 모호성과 비모호 원본 판정의 표기는 실제 boolean을 반영하고, 두 경우 모두 사용자 초안 및 retained 후보에 대한 조건부 결과임을 표시한다.
- blur와 화면 숨김에서는 draft 처리 예외를 기존 disarm·녹화 정리와 별도 listener로 분리한다. 두 정상 handoff 대기 상태에서는 초안을 stale·전송 불가로 보존하고, 지도·교정·pair 세대 변경이나 다른 오류에서는 폐기한다. 실행 중 초안 사용을 위한 재확인과 실제 pose 전송은 별도다.
- private proof의 일관된 내부 값 변경에 관해 처음 제기한 P2는 철회했다. 확인 API에서 클라이언트의 proof 주입은 거부되고 readback은 복사본이다. 합성 반례는 신뢰된 내부 값을 직접 수정한 경우의 validator 한계를 보여주었으며, 실제 API에서 도달 가능한 결함을 입증하지 못했다.

## Deadline 및 확인 동의 후속 검토

CI에서 보고된 proof 검증 오류의 당시 timestamp는 기록되지 않아 직접 원인은 확정되지 않았다. 별도 합성 반례에서는 생성된 부동소수점 deadline을 빼기로 재검사할 때 120초를 초과한 값으로 반올림되어 거절될 수 있었다. Backend·UI·통합 assertion 후보는 해당 경계를 생성식과 같은 `accepted < expiry <= accepted + 120`으로 비교한다. 독립 읽기 검토에서 해당 변경 범위의 추가 결함은 발견하지 못했다. 별도의 현재 시각 기준 빼기 검사는 이번 범위 밖이며, 생성식의 반올림 경계는 정확한 실수 시간 기준의 엄격한 120초 상한과 같다고 단정하지 않는다.

동일한 제안·proof·문맥의 일시적인 신선도 만료 동안 명시적으로 체크한 조건부 동의를 보존하되, 신선한 상태가 다시 확인되기 전에는 confirm을 비활성화하는 UI 후보를 검토했다. 첫 후보에는 새 명시 제안 요청 시 이전 proof binding이 남아 새 요청이 무효화되는 결함이 있었다. 후속 후보는 새 요청에서 이전 binding과 동의를 초기화하고 같은 요청 안의 proof 변경은 계속 차단하도록 수리했다. 이 수리는 코드 읽기 범위에서 확인했다. 추가 후보는 체크 동작 중 신선도가 만료되어도 동일하게 검증된 proof에 대한 명시 동의를 받을 수 있게 하며, confirm에는 여전히 신선한 확인을 요구한다. 어느 변경도 실제 현장 동작의 증거는 아니다.

Full-app confirm click의 timeout은 당시 체크박스 상태가 계측되지 않아 직접 원인이 확정되지 않았다. 별도의 DOM 진단 후보는 기존 click을 재시도하거나 강제하지 않고 화면 상태를 제한적으로 관찰한다. 표본 간 짧은 전이를 놓칠 수 있으며 계측 자체가 타이밍에 영향을 줄 수 있다. 후속 합성 fixture 후보는 주입한 상태 오류를 reload 전에 소비했는지와 복구 후 handoff·세션을 구조적으로 확인하고, 계측을 첫 확인 동작 전으로 옮겼다. 구현자 보고상 대상 component 한 건과 후속 합성 full-app 8단계가 통과했다.

개별 회귀의 PASS는 구현자가 보고한 합성 테스트 결과다. 독립 역할은 후보와 보존 증거를 읽었으며 광범위 suite를 재실행하지 않았다. C0의 최종 합성 snapshot 검사 보고는 Node 739건, assertion helper 7건, browser 79건, ASGI 31건 및 full-app 8단계 PASS이며, Python은 3,400 PASS·선택 항목 2 SKIP 이후 Python 소스 변경이 없었다. 이 역할은 해당 suite를 독립 재실행하지 않았다. CI 결과는 별도로 확인해야 한다.

합성 full-app의 fresh preparation 조회에서 기록된 `MATCH_ARMED`는 정합 요청 접수를 뜻한다. 그 뒤 현재 health sample 없이 수행된 별도 manager 조회는 `OUTCOME_UNKNOWN`으로 남았으며, C1.1의 읽기 분석은 이를 해당 조회의 fail-closed 경로로 설명한다. 두 조회는 동시 표본이 아니고, 어느 쪽도 실제 센서 건강이나 정합 수렴을 증명하지 않는다.
