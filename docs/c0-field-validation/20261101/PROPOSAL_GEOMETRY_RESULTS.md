## 유지하는 한계

이 기능은 모호한 위치 후보를 자동으로 확정하거나 지도 기준값을 임의 생성하지 않는다. N1의 `GLOBAL_AMBIGUOUS` 결과를 채워 넣지 않는다. 사용자 XY/yaw 초안은 새 검색 prior로 전달되지 않는다. 실제 제안이 거절되면 높이·기울기는 계속 미확인으로 남고 실패 사유를 표시한다.

확인된 geometry는 운영 위치추정·TF 반영·Nav2 준비 완료와 다르다. 정확한 관측 종료 확인과 이후 기존 준비 단계가 필요하며, 새로고침이나 값 표시로 다음 단계 명령을 보내지 않는다.

## 독립 검사와 최초 실패 보존

C1.4는 새 지도 변환 함수에 1.2초 합성 지연을 넣었다. 최초 구현은 변환 전에 pose age를 계산해 약 1.203초 뒤에도 약 0.012초 age와 ready 후보를 반환했다. C0의 추가 회귀에서도 변환 지연과 변환 도중 지도 변환값 변경 두 경우가 수리 전 FAIL이었다. 실제 장비 지연 또는 오래된 값의 실제 적용을 입증한 결과는 아니다. 변환을 기존 최종 지도·관측·출처·신선도 검사 앞으로 옮겨 원래 표본의 경과 시간을 보존하도록 수리했다. 신선도 기준을 완화하거나 새 표본의 시각을 이전 값에 덮어쓰지 않는다.

독립 재검토는 지연 회귀가 현재 source의 만료에서 먼저 거절될 수 있다는 검증 한계를 지적했다. 이를 분리한 별도 합성 검사에서 지연 후 새 시각의 exact pair를 공급하고 실제 source 검사가 새 pair를 수락하는 것을 확인했다. 그 상태에서도 이전 proposal pose는 `stale / OBSERVATION_INPUTS_UNAVAILABLE`이고 후보는 null이었다. 새 센서 입력의 신선도가 이전에 계산한 자세의 경과 시간을 초기화하지 않는다는 근거이며, 제품 코드를 변경하거나 실제 센서 값을 위조해 적용한 작업이 아니다.

역할별 추가 검사 중 sandbox Python 계약 검사는 8건 통과 후 비동기 사례가 진행되지 않아 중단됐다. 전체 성공으로 집계하지 않는다. UI 역할의 관련 회귀 19건 실행도 C0의 통합 검사와 중복을 피하기 위해 중단됐으며 통과 건수로 집계하지 않는다. 원본 로그는 비공개 증거 디렉터리에 보존했다. 테스트 파일에 기본 ruff 전체 규칙을 적용한 별도 실행의 46건 지적은 원본 HEAD에도 동일하게 존재했고, CI의 제품·scripts 범위 검사와 구분한다.

## 장비와 후속 적용

N1 문서에 기록한 map1/map1_2D ID·revision·교정 및 설정은 과거 검증 기록으로 유지한다. 이번에 장비 파일·설정·정책을 변경하거나 활성 정책을 새로 조회하지 않았다. 이전 e24→99 배포 후보는 정확 99 전용이므로 이번 변경에 사용하지 않는다. 새 배포 시 새 target용 archive/delta와 기존 백업·selector/lifecycle 경로를 사용하고, 현재 실제 base가 예상 e24와 다르면 기존 도구를 실행하지 않는다. 현재 현장 조건·소유권·정지/회수 수단을 확인한 작업 범위에서만 적용한다.
