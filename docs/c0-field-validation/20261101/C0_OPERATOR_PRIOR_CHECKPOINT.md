# C0 checkpoint: 사전 위치 초안과 센서 초기값

사용자가 현재까지의 작업 정리와 역할별 직접 커밋을 요청해 진행 중인 구현을 checkpoint로 보존한다. 기준은 `f50989a37b0203634f8dccefc4d149edafe0eadc`, 지정 브랜치는 `review/20261030-c0-3d-field-sweep`이다. 이 문서는 C0의 계약·관측·독립 반례와 통합 판단을 기록한다. C1.1~C1.4의 코드·검사·리뷰는 각 역할의 별도 커밋과 문서에 속한다.

## 사용자 흐름과 계약

1. 지도 조합을 확인하고 기존 아래 INITIAL POSE 도구로 현재 위치·방향의 **미전송 초안**을 받는다. XY 반경·방향 범위는 빈 값에서 사용자가 입력하며, 정지한 현재 위치라는 명시 확인을 받는다.
2. 현재 센서 스캔·동일 시각 자세와 저장 3D 지도의 후보를 초안과 같은 navigation-map/base_link 좌표·시각으로 비교한다. 높이·roll·pitch는 검증된 센서 정합 가설에서만 얻고, 초안이나 IMU 상대 자세만으로 채우지 않는다.
3. geometry 명시 확인과 정확한 관측 종료·handoff를 거친 뒤 기존 Nav2/TF 제어를 사용한다.
4. 현재 지도·실행 문맥에서 사용자가 초안을 명시적으로 재확인하고 실제 INITIAL POSE 전송·접수를 확인한 후 기존 정합 시작을 사용한다.
5. 보정 갱신·신선도·잔차·겹침 및 TF/Nav2 반영으로 현재 추정을 확인한다.
6. 별도의 유효 이동 범위와 기존 주행 검사를 충족한 뒤 goal을 전송한다.

표시 단계의 묶음이 기존 내부 검증 순서를 제거하지 않는다. Nav2·INITIAL POSE·goal 버튼은 위 패널에 중복 생성하지 않는다. 새로고침·센서 재시작·Nav2 전환으로 자동 전송하거나, 사용자 점을 센서 후보 XY로 덮어쓰지 않는다.

`operator_prior`를 사용한 모든 결과는 원래 전역 결과가 단일이더라도 `CONDITIONAL_ON_OPERATOR_PRIOR`로 표시하고 범위·TTL·서버 proof를 검사해야 한다. 원본 `ambiguity_unresolved`의 true/false는 그대로 보존한다. 0개 또는 복수 후보는 거절하며, 하나여도 사용자 초안이 맞다는 전제와 이번에 남겨진 제한 후보 집합 내의 판단일 뿐 전역 유일성·실제 위치 정확도가 아니다. 기존 품질·source·교정·지도·세대·정지·stop receipt·일회 사용 검사는 유지한다. 확인 시 현재 전파 pose와 이후 INITIAL POSE는 모두 사용자 prior 범위 및 기존 0.25m/0.20rad 인계 경계를 만족해야 한다.

현재 구현 후보는 기존 backend의 `duplicate_of`를 별도 동치군으로 합치지 않는다. 중복 수렴을 독립 후보로 세어 안전하게 거절하는 사용성 문제가 남아 있으며, 이번 저장에서 새로운 중복 임계값이나 선택 정책을 도입하지 않는다.

## 실장비 관측과 오프라인 결과의 구분

| C0 항목 | 결과와 한계 |
|---|---|
| 과거 N3 정지 관측 | 유효 센서 증거를 확보하고 proposal 1회를 계산했으나 `GLOBAL_AMBIGUOUS`로 거절됐다. geometry 확인·적용 0회이며 Nav2·INITIAL POSE·goal·이동도 0회였다. |
| N3 복구 | 정확한 관측 세션 종료와 이전 source/bridge 복구 및 보호파일 무결성 확인을 완료했다. N3는 종료됐으며 현재 물리 상태나 새 시험창을 증명하지 않는다. |
| 기존 f509 오프라인 선행 검사 | 실제 UI/ASGI 합성 경로 5 PASS, 저장 합성 수치 대조 3 PASS. 새 prior 구현의 통합 성공이나 실제 센서 초기값 적용 증거가 아니다. |
| 과거 후보 변환 | 고정 backend 원본 7파일의 hash를 대조하고 SE(3) 및 문맥을 검사했다. 과거 retained 후보 10개를 분석했으며 현재 위치나 새 적용 근거로 재사용하지 않았다. |
| 사용자 초안 조회 | 사용자는 표시 완료라고 답했으나 C0가 읽은 화면은 준비 조회 실패와 빈 좌표였다. 읽기 전용 재조회 1회 후 준비 상태는 복구됐으나 좌표는 없었다. 실제 사건의 원인은 확정하지 않았다. |
| C0 반례 A: 전역 단일 결과의 prior 무시 | 초기 후보에서 범위 밖 전역 단일 결과가 ready geometry로 통과하는 합성 FAIL을 보존했다. 해당 snapshot의 파일 hash 전후가 같음을 확인했다. C1.1에 모든 prior 요청의 범위·조건부 proof 검사 수리를 전달했다. |
| C0 반례 B: 알 수 없는 후보 gate 제외 | 초기 후보가 unknown gate를 가진 다른 후보를 제외하고 단일 후보를 선택하는 합성 FAIL을 보존했다. 알려지지 않은 gate는 거절하도록 C1.1에 전달했다. |
| C0 실제 알고리즘 합성 검사 | 고정 Open3D backend로 합성 self-registration 1회를 실행했다(2.276초). 원본 전역 결과는 gate 없음·선택 index 0, retained 6개 중 5개는 `duplicate_of: 0`이었다. 새 조건부 selector는 `PRIOR_MULTIPLE_MATCHES`로 거절했다. 알고리즘 실행 증거이며 실장비·센서 정확도 검증이 아니다. |

최초 실패를 이후 수리 결과로 덮지 않는다. C1.1의 수리 및 회귀 통과 보고는 해당 역할 문서에 기록하며, C0가 새 통합 snapshot을 독립 재실행한 결과로 표현하지 않는다. C0 실제 알고리즘 합성 실행은 당시 작업 후보를 사용했고 실행 전후 전체 후보 hash를 고정하지 않았으므로 최종 커밋 전체 검증으로 주장하지 않는다.

별도 설명 채팅에서 전달한 센서 초기값 인계서는 위 계약과 대조했다. 현재 스캔의 저장 지도 정합, 이미 실행 중인 신선한 지도 추정, 현장에서 독립 확인한 수동 값은 서로 다른 근거다. 실행 중 추정이 아직 없는데 이를 최초 시작의 필수 근거로 사용하는 순환 의존을 만들지 않는다. 해당 인계서를 새 구현이나 현장 승인으로 취급하지 않았다.

## 남은 작업과 복구

- backend/UI의 정확한 통합 snapshot에 대한 실제 ASGI↔UI 및 ①~④ 흐름, 전체 회귀와 독립 최종 검토는 별도 확인이 필요하다. 역할별 단위·부분 검사와 합산해 전체 성공으로 표시하지 않는다.
- 기존 backend 중복 표시를 안전하게 재사용할지, 경계에 걸친 중복과 서로 다른 높이·기울기를 어떻게 구분할지 결정해야 한다. 현재 거절을 성공으로 바꾸기 위해 gate를 약화시키지 않는다.
- 실장비 geometry 확인·적용, 이후 Nav2/TF·INITIAL POSE 접수·운영 정합·연속 위치추정·P1/P2 주행은 미완료다. 새 배포·관측·이동은 이번 checkpoint 범위에 없다.
- bridge 공존 사이드채팅 변경과 C1~C7/D1~D3 확장 브랜치는 포함하지 않았다. 지도·교정·센서·주행 설정을 변경하지 않았다.
- 장비의 마지막 검증된 배포는 f509이며 이번 저장으로 변경되지 않는다. 후속 배포는 실제 base·보호파일·소유권·현재 현장 범위를 확인하고 기존 백업·selector/lifecycle 복구 절차로 수행한다. base가 달라지면 과거 도구를 그대로 실행하지 않는다.

원본 센서·지도·장비 식별값·상세 회수 경로와 사적 증거는 로컬 증거 저장소에 보존한다. 공개 Git에는 소스·합성 검사·계약·검증 범위와 요약만 포함한다.
