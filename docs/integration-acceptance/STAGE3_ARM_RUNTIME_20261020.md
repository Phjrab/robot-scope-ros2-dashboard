## 현재 결과

저장된 3D 지도에 대한 정지 상태 LiDAR 전역 탐색을 로봇의 새 대시보드에서 실행했다. 전역 작업은 완료됐지만, 결과는 **모호성이 남은 과거 시점의 센서 위치 후보**다. 이어 시작한 짧은 로컬 추적은 0.6초 처리 제한을 넘어 `LOST`가 됐다. 현재 로봇 몸체의 위치·방향과 연속 이동 궤적은 검증되지 않았다. 이동, 자세 변경, Nav2 목표, `cmd_vel` 발행은 실행하지 않았다.

사용자가 정한 **RMSE 0.10m 이하는 잠정 잔차 비교 기준**이며 기존 0.05m 결과도 함께 표시한다. 두 수치는 원본 입력 스캔 전체와 지도 전체를 최근접 조회한 뒤, 원본과 같은 거리 0.75m 이내 대응점의 `rmse_m`으로 비교한다. 전체 스캔 RMSE는 별도 값이다. 최신 관측은 16,000점 전부가 대응돼 `rmse_m`과 전체 스캔 RMSE 모두 0.1696802901m였으며, **0.10m와 0.05m 모두 통과하지 못했다**. 현재 구현의 숫자 비교를 모호성 해제나 실제 위치 정확도 판정으로 승격하지 않는다. 수렴·모호성·겹침률·좌표·시간·신선도 검사는 별개다.

## 보존·복구와 남은 근거

제품 37개 대상 경로와 환경 파일의 기존 바이트·권한을 로봇의 권한 제한 백업 `/home/unitree/robot-scope-diagnostics/stage3-deploy-20261020/apply-backup-01`에 보존했다. 환경 파일에서는 backend 연결용 4개 항목만 갱신했고 제어 환경 파일과 서비스 unit은 변경하지 않았다. 필요하면 전역/센서 worker를 중지·정리한 뒤 해당 37경로의 원래 존재 여부·바이트·모드와 환경 파일 원본을 복원하고 대시보드 서비스만 재시작해 health, 센서 source, 지도·설정 해시를 다시 확인한다. 비밀번호·토큰·키와 환경 파일 내용은 이 보고서에 포함하지 않는다. 현재 서비스가 건강해 롤백은 실행하지 않았다.

현재 위치·방향을 본체 pose로 표시하려면 XT16, IMU 및 `base_link` 사이의 실측 변환과 적용 방향, 독립 기준점으로 측정한 위치 정답이 더 필요하다. 원본 capture clock과 로봇 수신 clock의 대응 및 epoch 근거도 독립적으로 필요하다. seq1063 발췌 CDR 352,196바이트와 대응하는 원본 JSONL 한 행은 이미 수신·보존됐다. 전후 연속 JSONL, 대응 IMU·odom·TF 기록과 맥북의 전체 실데이터 보고/로그가 더 있어야 시각 대응과 발췌의 맥락을 대조할 수 있다. 0.6초 안에 전체점 채점을 유지한 로컬 처리가 끝나는지 확인하고, 새 스캔 3회 이상에서 시간적 일관성·유실·재탐색을 검증해야 한다. 이동 중 시험은 별도 현장 준비와 승인이 필요하다.

## 처리 시간 실험과 제품 반영 여부

격리 저장 입력(스캔 1 전체 16,000점, 지도 전체 25,666점, 스캔 0의 기존 seed)으로 두 시제품을 시험했다. 원본 backend 파일, 원본 세 refinement 분기, 전체 입력의 채점 방식은 유지했다.

- plane refinement만 겹친 첫 시제품: 직렬 진단 0.8122초, 병렬 진단 0.6252초. 별도의 0.6초 제한 시험 두 번 모두 시간 초과였다.
- 세 분기의 refinement와 전체점 score를 겹친 두 번째 시제품: 직렬 진단 0.7943초. 0.6초 제한 시험은 한 번 0.5799초로 완료, 한 번 시간 초과였다. 별도 5초 진단 상한에서 완료된 실행은 0.5697초였다. 5초는 격리 진단의 상한이며 제품의 제한 변경이 아니다.
- 완료된 직렬/병렬 결과는 비시간 필드, 후보·gate와 233개 부동소수점 값이 정확히 같았다. 각 후보는 스캔 16,000점 모두를 채점했다. 두 번째 시제품의 결과 봉투는 약 10,054바이트였다. 강제 2초 지연은 0.6초에서 거부됐고 소유한 자식은 모두 종료·회수됐다.
- 두 번째 실험의 실행 파일 SHA-256은 `8755016db7c1929066b486e5043a0bd27a2380b0650990e76ead84ef7939bdbe`다. 실행본은 부모의 실행 전 source 검증, 자식 import 뒤 입력 검증, 실행 후 검증을 수행했다. 이후 준비한 자식 import 전 추가 검증판은 이 ARM 결과의 실행본이 아니다.

**두 시제품 모두 제품에 반영하지 않았다.** 원본 `SE3Observation`의 직렬 사용 계약과 Open3D 동시 실행 안전성이 입증되지 않았고, 실제 제품의 부모 preflight·파일 전달·IPC를 포함하지 않은 실험에서도 0.6초를 안정적으로 통과하지 못했다. 별도 프로세스로 각 분기를 분리하는 방식은 후속 검토 대상이다. 원본 세 분기나 채점 입력을 줄이거나 시간·신선도 제한을 늘리는 변경은 하지 않았다.

## 이번 후속 커밋

`test_robot_scope_acceptance.py`의 읽기 수집 시험이 실제 데스크탑의 `~/ws/go2_3d` 권한에 의존하던 문제를 수정했다. 소유권이 분리된 임시 디렉터리와 해당 시험의 환경 변수만 사용하고, 지도·로그 권한 검사가 실제로 PASS인지 명시적으로 확인한다. 제품의 권한 검사는 그대로다. 이 수정 뒤 로컬 전체 Python 2,571건(2,568 통과·3 skip)과 JavaScript 시험 파일 65개 그룹이 통과했다. 원래 보존 중인 로컬 변경 10파일은 수정·배포·커밋에 포함하지 않았다. 따라서 이 checkout의 시험 개수와 공개 커밋의 시험 개수는 다르다.

이 문서의 CI 표는 `debba9c`의 완료 결과다. 이 시험 수정과 보고서의 새 커밋은 별도의 GitHub Actions 결과로 확인해야 하며, 이전 커밋의 성공을 새 커밋의 성공으로 간주하지 않는다. 공개 대상은 `codex/maps-localization-integration` 브랜치이며 main 병합이나 force push는 하지 않는다. 원본 backend 소스, 가상환경·빌드 파일, 환경 파일, 비공개 수업자료 및 인증정보는 공개하지 않는다.
