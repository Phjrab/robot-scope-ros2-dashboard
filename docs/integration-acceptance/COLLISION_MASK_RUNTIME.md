# Opt-in native collision-mask publication and Humble profile

Status: SOFTWARE IMPLEMENTATION. The immutable artifact now has a native ROS
publisher, a separate opt-in circle collision profile, and a publication identity
readback connected to the production policy observer. Publication is not native
costmap ingestion. All runtime policy enforcement scopes remain false pending
qualified ingestion, controller, replanning and current map-binding evidence.
This unit does not gate Stereo VSLAM and does not enable driving.

## Exact input and source identity

`navigation_collision_profile.load_collision_mask` requires an absolute real
artifact directory and its exact expected artifact digest. It reads bounded
regular files with no symlink following, rejects duplicate JSON keys and invalid
geometry, and reconstructs the whole original artifact from source occupancy and
annotations. Every generated byte and the digest must match. Rehashing a forged
mask or manifest cannot bypass reconstruction. Input bytes and source maps remain
unchanged. The publisher uses this verified immutable in-memory snapshot; it does
not reopen files or treat later catalogue changes as a fresh version of the same
artifact. Current catalogue/map-epoch verification remains a separate requirement.

`scripts/run_navigation_collision_mask.py --artifact ABS --artifact-digest HEX`
starts only the mask publisher in the caller's explicit ROS environment. It does
not select or alter an operating DDS environment, launch Nav2, publish TF or
velocity, send goals, clear costmaps, or change services. The fixed node is
`/robot_scope_collision_mask`, with exactly these data topics:

| Topic | Message | QoS and purpose |
|---|---|---|
| `/robot_scope/navigation/collision_mask` | `nav_msgs/OccupancyGrid` | Reliable, transient-local, depth 1; one immutable mask |
| `/robot_scope/navigation/collision_mask_binding` | `std_msgs/String` | Reliable, volatile, depth 1; publication identity heartbeat every 250 ms |

The mask preserves ROS row order, resolution, origin quaternion and frame. Its
0/100 values are derived from the geometry builder; original unknown bytes remain
preserved separately. The binding includes artifact/mask hashes, all six map-family
pins, annotation revision, frame/topic, a random process incarnation and advancing
sequence. It explicitly reports `evidence_kind: publication_only` and
`runtime_policy_enforced: false`. No private filesystem path appears in it.

Each publication requires exactly one graph authority with the fixed node identity
on both topics. Duplicate/foreign/missing/changing authorities stop publication;
the CLI destroys its node on failure. Initial discovery may wait at most three
seconds for its own writers, without publishing during that window. DDS graph
observations are not an exclusive distributed lock or an authenticated ingestion
witness. A costmap retaining the last grid after publisher loss does not keep the
source heartbeat fresh.

## Explicit native consumer profile

`make_collision_profile(base, artifact, robot_radius_m=..., footprint_padding_m=...,
bt_xml_path=...)` returns a new `{parameters, manifest}` object and never mutates
the installed base. Radius and padding are mandatory finite values; there is no
authoring/default-radius fallback. This first native profile supports circular
footprints only, with source frame `map` and exactly zero origin yaw. Rotated
offline artifacts remain valid, but Humble StaticLayer origin rotation is not
assumed to work. Polygon footprints and unknown plugin/filter layouts are rejected.

The profile is `robot-scope.humble-solid-mask-circle.v1`:

- Both global and rolling local costmaps add `policy_layer`, a native StaticLayer,
  after obstacle layers and before inflation. Its immutable map topic is fixed;
  transient-local map subscription is enabled, incremental updates and footprint
  clearing are disabled. Humble costmap-level `use_maximum`, `track_unknown_space`,
  `unknown_cost_value`, `lethal_cost_threshold` and `trinary_costmap` are explicit.
  This is intended to retain original obstacles while adding source non-free and
  KEEP_OUT obstacles; actual ingestion and clear retention require native checks.
- Navfn disallows unknown and uses exact goal tolerance zero. Inflation radius is
  at least explicit radius plus padding plus one costmap resolution. This config
  is not a proof of passage clearance or footprint collision behavior.
- `FollowPath` uses direct RegulatedPurePursuit with collision detection enabled.
  The unqualified rotation-shim wrapper is removed from this opt-in profile.
- The shipped `config/robot_scope_collision_replan.xml` defines a fixed
  ComputePathToPose/FollowPath pipeline with 1 Hz replanning and no recovery motion
  or costmap clearing. It is selected only for NavigateToPose. Other navigation
  action trees are not covered by this profile's evidence contract.

The profile manifest pins the exact artifact, map family, annotation revision,
circle dimensions, tree bytes and all generated parameters. Its digest excludes
wall time; the actual absolute tree path is included in the parameter digest.
The manifest still declares no native-ingestion/enforcement evidence.

## Production readback and admission boundary

`RosPolicyReadback` retains the same five nodes, ten asynchronous service requests,
500 ms deadline and 250 ms timer. It additionally requests effective policy-layer
and costmap-level parameter names and subscribes to the fixed binding topic.
Callback message publisher GID must match the unique binding authority, both mask
authorities must be present, and sequence must advance within an incarnation.
Changing the immutable payload or GIDs within an incarnation invalidates it.
Malformed/foreign/replayed data does not refresh receipt time. No remote exception
or arbitrary binding text is exposed.

When no mask source exists, the previous readback shape and behavior remain.
Once observed, `collision_mask_source` contains separate publication evidence.
The existing 750 ms freshness boundary is used without relaxation; age starts at
local callback receipt and does not assert transport latency or native ingestion.
Graph loss is checked independently of parameter-readback completion. A restart
with a new source incarnation can provide new publication evidence, but cannot
reuse the old semantic identity.

`RuntimePolicyProvider` exposes bounded publication evidence with
`native_ingestion_verified: false`. Artifact, map/annotation identity, frame,
incarnation and endpoint GIDs participate in the semantic policy revision;
sequence, age and current/stale status do not. A valid source heartbeat cannot
remove `POLICY_MASK_INGESTION_UNVERIFIED`,
`POLICY_CONTROLLER_COLLISION_UNVERIFIED` or `POLICY_MAP_BINDING_UNAVAILABLE`.
There is still no positive enforcement branch based solely on parameters, plugin
names, a published grid, or a successful planner path.

## Software verification and native acceptance contract

Focused software checks cover semantic reconstruction, payload/pin tampering,
symlinks/FIFO/size bounds, unchanged source bytes, explicit circle/profile binding,
rotated-map refusal, fixed BT actions, ROS-shaped grid/QoS serialization, source
conflicts/restarts, freshness, replay rejection, and production policy projection.
The tests use fake ROS transports and do not claim actual Nav2 execution.

The independent native harness must pin source/profile/artifact/configuration and
use an isolated non-operating DDS domain, synthetic map and private TF. Minimum
remaining producer tests are both global/local raw costmap ingestion, unknown and
KEEP_OUT cells, clear retention, exact circle/narrow-passage behavior, native
parameter readback, publisher loss/restart, and new map/annotation epochs. A
ComputePath-only run can validate planner/costmap behavior; it cannot attest actual
FollowPath/controller collision decisions, BT internal replanning or active-run
policy-loss cancellation. Those remain separate native evidence requirements.

No launcher, default deployment, camera service, operating TF, initialpose, lease,
navigation goal or robot motion is introduced by this implementation.
