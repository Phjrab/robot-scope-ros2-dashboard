# 카메라 pose와 Go2 본체 pose의 실측 준비

현재 별도의 실측 자료가 없다는 사용자 확인에 따라, 독립 정답 기반 정확도와
본체 pose 검증 결과는 **미수행**으로 유지한다. 이 준비는 Stereo VSLAM 관측과
새 지도 작성의 선행 조건이 아니다. 현재 대시보드 pose는
`vslam_lab_camera_link` 기준이며 Go2 본체 pose로 바꾸어 부르지 않는다.

## 먼저 확보할 자료

1. **장착 상태 기록:** 카메라 시리얼, 브래킷/장착 위치, 장착 사진, 흔들림 유무,
   측정 날짜를 기록한다. 카메라나 브래킷을 재장착하면 별도 장착 버전으로 남긴다.
2. **본체 기준점과 축:** 사용할 Go2 `base_link`의 실제 원점과 방향을 제조사
   도면이나 검증 가능한 기구 기준으로 정한다. x=앞, y=왼쪽, z=위다.
   외장 덮개의 임의 점을 본체 원점으로 대신하지 않는다.
3. **카메라→본체 보정:** 정확한 카메라 frame에 대해 본체 기준
   x/y/z 위치(m)와 회전(quaternion `[x,y,z,w]` 또는 회전행렬)을 측정한다.
   측정 방법·장비·원본 파일과 위치/각도 오차 범위도 함께 필요하다.
   카메라 외장 표면과 광학 중심은 다르며 `camera_link`와 optical frame도 다르다.
4. **외부 정답 pose:** 외부 카메라와 실측한 강체 표적, 모션캡처, 또는 자세까지
   측정하는 레이저 트래커 등으로 `시간 + 본체 위치 + 본체 회전`을 기록한다.
   표적과 본체 사이의 고정 변환도 실측해야 한다.
5. **좌표계·시간 관계:** 외부 기준 좌표와 VSLAM 지도 사이의 고정 변환,
   두 기록의 시계 차이·변동 범위·timestamp 단위를 정한다. 평가할 VSLAM
   궤적에 맞추어 변환이나 시간 차이를 사후 최적화하지 않는다.

줄자·거리계만 있다면 우선 장착 치수와 기준점 간 거리를 기록할 수 있다.
이는 거리에 대한 제한적인 확인 자료다. 한 점의 위치나 거리만으로
독립적인 회전 정답이나 정밀 6DoF 보정을 확보했다고 판정하지 않는다.
장비를 마련하기 전에는 측정하지 않은 값을 추정하거나 오차를 0으로 채우지 않는다.

## 한 측정 기록에 적을 값

| 항목 | 기록 예시 형식 — 숫자는 실제 측정 후 입력 |
|---|---|
| 부모 / 자식 frame | `base_link` / `vslam_lab_camera_link` |
| 위치 | `x, y, z` — m |
| 회전 | `qx, qy, qz, qw` — 단위 quaternion |
| 방향 정의 | `T_parent_child`: 자식 좌표를 부모 좌표로 변환 |
| 불확실성 | 위치 상한 m, 회전 상한 rad, 산정 근거 |
| 출처 | 장비 ID, 측정 방법, 날짜, 장착 ID, 원본 파일 |
| 시간 | 시계 종류, 원본 timestamp, 상대 시계 offset과 그 오차 |

본체 pose 계산에 쓰는 식은 다음과 같다. 변환의 방향을 반대로 넣지 않는다.

`T_world_body = T_world_map × T_map_camera × inverse(T_body_camera)`

약 49.9 mm의 좌우 카메라 간격은 stereo baseline이며 본체 장착 위치가 아니다.
현재 보존한 CameraInfo와 카메라 내부 TF는 이 내부 관계를 확인하는 자료다.

## 자료가 생긴 뒤의 최소 순서

1. 장착·frame·시간 관계와 원본 파일을 먼저 검토한다.
2. 로봇을 움직이지 않고 외부 정답과 VSLAM pose를 동시에 반복 기록한다.
3. [입력 양식](pose_precision_input.example.json)을 private 디렉터리에 복사해
   실제 값과 원본 파일 hash를 채운다.
4. `scripts/evaluate_pose_precision.py`로 일대일 timestamp 대응, 위치/회전
   오차와 누락 표본을 계산한다. 자동 정렬·보간·scale fitting은 하지 않는다.
5. 정지 결과는 해당 위치에서의 오차·흔들림으로만 보고한다. 주행 궤적의
   정확도·장거리 drift와 운영 TF 적용은 별도 검증 및 승인 범위다.

수학·입력 검증·결과의 한계는
[정밀평가 계약](POSE_PRECISION_CONTRACT.md)에 기록한다.
계산 성공만으로 측정의 독립성이나 본체 보정의 품질이 인증되지는 않는다.
