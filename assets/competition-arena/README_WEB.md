# 경기장 로컬 웹 미리보기

`web/`는 실제 `arena.glb`를 Three.js로 표시하는 독립형 정적 뷰어입니다. 사진이나 정적 이미지로 대체한 모형 화면이 아닙니다. 이 작업은 로컬 파일 제작이며 외부 게시, 배포, 업로드 또는 RobotScope 저장소 변경을 포함하지 않습니다.

## 1. 실행

Python 3이 있는 컴퓨터에서 압축을 풀고 **`arena.glb`, `arena.json`, `web/`가 함께 있는 폴더**로 이동합니다.

```bash
cd competition_arena
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 다음 주소를 엽니다.

```text
http://127.0.0.1:8000/web/
```

- Windows에서 `python3` 명령이 없으면 `py -m http.server 8000 --bind 127.0.0.1`을 사용합니다.
- `index.html`을 더블클릭하는 `file://` 방식은 모듈과 GLB/JSON 로딩 제한 때문에 지원하지 않습니다.
- `web/` 폴더만 서버 루트로 삼으면 상위 모델 파일을 읽을 수 없습니다. 전체 `competition_arena` 폴더에서 서버를 시작하세요.
- 서버 종료: 터미널에서 `Ctrl+C`.
- `127.0.0.1`에만 바인딩하므로 같은 컴퓨터에서만 접근할 수 있습니다. 외부 공개 서버가 아닙니다.
- Three.js를 함께 포함했으므로 실행 시 인터넷 연결, npm 설치, API 키, CDN, 로그인은 필요하지 않습니다.

## 2. 조작

| 기능 | 조작 |
|---|---|
| 입체 보기 | 원근 투영. 왼쪽 드래그 회전, 오른쪽 드래그 이동, 휠 확대/축소 |
| 평면 보기 | 정사영. 화면 오른쪽이 원본 +X, 화면 위쪽이 원본 +Y. 드래그 이동, 휠 확대/축소 |
| 초기화 | 입체 시점, 모든 레이어 표시, 선택 해제 |
| 레이어 | 바닥·구역 / 벽·경계 / 장애물·경사로 / 라벨·치수선 / 1 m 격자 |
| 객체 선택 | 짧게 클릭하면 객체 이름, 원본 메타데이터 및 모델 외접상자 표시 |
| 선택 해제 | 빈 배경 클릭, `Esc`, 또는 ‘해제’ |
| 치수와 가정 | ‘전체 치수 · 추정 근거 보기’에서 모든 치수·가정·객체 메타데이터와 원본 JSON 확인 |
| 터치 | 입체에서 한 손가락 회전, 두 손가락 이동/확대 |

화면의 계층 분류는 GLB의 객체 이름과 `category` 메타데이터를 사용합니다.

- `floor_`, `zone_`, `ground_` → 바닥·구역
- `wall_` → 벽·경계
- `ramp_`, `stair_`, `signal_`, `obstacle_` → 장애물·경사로
- `label_`, `marking_`, `dimension_`, `annotation_` → 라벨·치수선

라벨·치수선 레이어에는 바닥 표식도 포함됩니다. `category` 메타데이터가 있으면 이름 접두어보다 우선하며, 중앙 평탄부 `platform`은 장애물 레이어에 포함됩니다. 레이어 색상 범례는 범주 안내용이며, 실측 여부를 나타내는 색상이 아닙니다. 명시/추정 여부는 치수 상태 및 `arena.json`의 `status`, `source`, `uncertainty`에서 확인하세요. 노란색 `†`는 추정 또는 계산으로 도출한 치수입니다.

## 3. 좌표와 단위

단위는 **미터(m)**입니다. 원본 Blender 및 `arena.json`은 다음 좌표계를 사용합니다.

- 원점: 전체 평면 외곽 경계의 왼쪽 아래, 바닥 기준
- +X: 평면 오른쪽
- +Y: 평면 위쪽
- +Z: 높이

Blender의 glTF 내보내기 단계에서 Z-up을 Y-up으로 변환합니다.

```text
Blender / JSON (x, y, z)  →  glTF / Three.js (x, z, −y)
glTF / Three.js (x, y, z) →  Blender / JSON (x, −z, y)
```

뷰어는 GLB를 **추가 회전, 이동, 리센터링 또는 배율 변경 없이** 로드합니다. 카메라만 모델을 향해 움직입니다. 이미 변환된 GLB에 다시 `rotation.x = -Math.PI / 2`를 적용하면 축이 틀어집니다.

선택 객체의 ‘외접상자’는 로드된 시각 모델의 world-axis-aligned bounding box입니다. 이 값은 회전된 객체의 로컬 길이와 다를 수 있으며, 실측값이나 실제 통과 여유를 보장하지 않습니다. 화면에는 이를 원본 X/Y/Z 순서로 환산해 표시합니다.

## 4. 모델 사용 제한

이 모델은 제공 자료를 바탕으로 만든 **시각 검토용 재구성**입니다. 모든 추정 치수, 가정 및 객체별 불확실성은 `arena.json`에 기록되어 있고 뷰어에서 확인할 수 있습니다.

다음 작업에는 현장 실측 및 별도 검증이 필요합니다.

- 실제 로봇의 충돌 검사, 경로 계획, 속도/보행 제어
- 센서 가림, LiDAR/카메라 관측성, 시뮬레이터 물성
- 벽 두께/높이, 경사로와 계단 치수, 바닥 높이, 장애물의 정확한 위치
- 지도 좌표계와 실제 경기장 사이의 위치·방향 정합

바닥 격자는 표시용 1 m 기준선이며 주행 가능/불가능 판정이 아닙니다. 시각 메시를 그대로 내비게이션용 costmap으로 취급하지 마세요.

## 5. 향후 RobotScope 연동 시 확인할 점

본 뷰어는 RobotScope의 현재 API를 사용하거나 코드를 수정하지 않습니다. 아래는 향후 연결 시 적용할 일반적인 어댑터 점검 사항입니다.

1. `arena.json`의 Z-up 원본 좌표를 유지할지, Three.js Y-up 좌표로 변환할지 한 곳에서 결정합니다.
2. GLB는 이미 Y-up이므로 시각 메시를 중복 변환하지 않습니다. `arena.json`의 위치·방향·치수와 GLB 간 매핑만 명시적으로 처리합니다.
3. 기존 로봇/ROS map 프레임과의 transform은 현장에서 측정합니다. 이 파일에 실제 로봇의 초기 자세나 TF 정합은 포함되어 있지 않습니다.
4. 시각 모델, 충돌 모델, 주행 가능 영역, 금지 구역을 별도로 관리합니다. 추정 geometry를 확정된 collision source로 승격시키지 않습니다.
5. 객체 `name`/`id`를 선택·숨김·메타데이터 연결 키로 유지합니다. 외부 에디터에서 이름을 변경하면 연결 키도 함께 갱신합니다.
6. 로딩 완료 후 bounding box, 미터 단위, 원점, 최소 세 개의 비공선 기준점, 회전 방향을 실제 지도와 대조합니다.

## 6. 구성

```text
competition_arena/
├── arena.blend                # Blender 편집 원본
├── arena.glb                  # 실제 웹 렌더링 모델
├── arena.json                 # 원본 좌표·치수·가정·객체 메타데이터
├── README_WEB.md              # 이 문서
└── web/
    ├── index.html
    ├── styles.css
    ├── app.js
    ├── vendor/                # Three.js 0.180.0 및 MIT LICENSE
    └── tests/
        └── smoke.mjs          # Playwright 브라우저 점검
```

Three.js 파일과 라이선스의 출처는 `web/vendor/README.md`를 참고하세요. glTF 2.0 GLBLoader와 OrbitControls를 사용하며, 외부 네트워크 요청이나 텔레메트리는 없습니다.

## 7. 재검증

이번 제작 환경에서 확인한 범위:

- **통과:** JavaScript 구문, 실제 Three.js GLTFLoader에 의한 GLB 파싱, 83개 메시/6,692개 삼각형, 83개 객체의 원본→glTF 바운딩박스 축 변환, 모든 메타데이터 객체 대응, 로컬 의존성 파일.
- **미검증:** 브라우저 GPU 렌더링, 시각 레이아웃, 마우스/터치 상호작용. 클라우드 실행 환경의 Chromium 소켓 권한 제한 및 승인 실행의 환경 설정 오류 때문에 브라우저를 실행하지 못했습니다. 웹 스크린샷은 제공하지 않았습니다.
- 구조 검증 결과는 `web-tests/structural-validation.json`에 있습니다. Blender가 생성한 모델 렌더와 웹 브라우저 검증은 별도입니다.

브라우저 없이 구조 검증을 다시 실행하려면 Node.js가 있는 환경에서:

```bash
node --experimental-loader ./web/tests/three-import-loader.mjs ./web/tests/validate-glb.mjs
```

브라우저 점검에는 별도로 설치된 Playwright와 Chromium이 필요합니다. 일반 사용자 열람에는 필요하지 않습니다.

```bash
# 위 HTTP 서버를 실행한 상태에서:
node web/tests/smoke.mjs http://127.0.0.1:8000/web/ ./web-tests
```

필요하면 `PLAYWRIGHT_MODULE` 환경변수에 설치된 Playwright 모듈의 절대 경로를, `CHROMIUM_PATH`에 Chromium 실행 파일을 지정할 수 있습니다. 테스트는 GLB 응답, 실제 메시 렌더링, JSON 로딩, 두 시점, 레이어 토글, 초기화, 상세창 반복 열기/닫기, 데스크톱/모바일 폭 및 외부 요청 부재를 검사합니다. 테스트 결과와 스크린샷은 지정된 출력 폴더에 저장합니다.

WebGL을 사용할 수 없는 브라우저에서는 모델 대신 명시적인 오류가 나타납니다. 최신 브라우저와 하드웨어 가속을 확인하세요.
