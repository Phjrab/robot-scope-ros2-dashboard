# 대회장 Blender 모델

첨부된 4장의 도면을 바탕으로 만든 시각화용 재구성입니다. 원본 CAD나 현장 실측 자료는 없으므로, 명시 치수와 계산 치수, 래스터 도면에서 추정한 형상을 구분했습니다. 로컬라이제이션 또는 Nav2용으로 검증된 지도가 아닙니다.

## 파일

- `arena.blend`: Blender 4.3.2 원본. 재질, 독립 객체, 카메라 2개, 조명 포함
- `arena.glb`: 웹/Three.js 등에 사용할 glTF 2.0 단일 바이너리. 미터 단위, Y-up
- `arena.json`: 원본 Z-up 좌표, 객체별 ID/치수/바운딩박스/근거/불확실성, GLB 축 변환
- `build_arena.py`: 외부 애드온 없이 재생성하는 Blender Python 스크립트
- `isometric.png`, `top.png`: 등각 및 정면 수직 평면 렌더
- `ASSUMPTIONS.md`, `ASSUMPTIONS.csv`: 적용한 치수와 추정 항목 보고서
- `validate_arena.py`, `validation.json`: GLB/JSON 구조, 객체, 축, 치수 검증 스크립트와 결과
- `web/`: 별도로 제작한 웹 미리보기. `README_WEB.md`의 실행 지침을 따르세요

원본 첨부 이미지는 변경하지 않았습니다. 모델 생성 스크립트는 추출 좌표를 자체 포함하므로 원본 이미지가 없어도 재실행할 수 있습니다. 소스 파일 해시는 `arena.json`에 기록됩니다. 기존 로컬 파일과 최신 재첨부의 파일 크기는 모두 일치하나 재첨부 바이너리의 독립 해시 대조는 수행하지 않았습니다.

## 좌표와 단위

기준 원점은 평면도 전체 경계 사각형의 **왼쪽 아래**, 주행 바닥 윗면 높이입니다.

- Blender/JSON: 미터, +X는 도면 오른쪽, +Y는 도면 위, +Z는 높이
- 도면 전체 범위: X=0..8.000, Y=0..6.018 m
- 평탄 주행면: Z=0; 바닥판 하부: Z=-0.06 m (바닥판 두께는 시각화 추정)
- 중앙 교차부 중심: (3.303, 3.009, 0) m (도면 추정)
- 중앙 평탄부 윗면: Z=0.18 m
- GLB 변환: `(x, y, z) → (x, z, -y)`
- GLB 범위: X=0..8.000, Z=-6.018..0, Y가 높이
- 내보내기 때 원점을 이동하거나 중앙 정렬하지 않았습니다

Three.js는 GLB 자체를 Y-up으로 불러오면 됩니다. JSON의 Z-up 좌표를 이용해 표식을 추가할 때 위 변환을 한 번만 적용하세요. JSON의 좌표와 회전은 원본 좌표 기준입니다. `bbox_m`와 `dimensions_m`는 실제 메시 정점을 변환한 월드 축 정렬 바운딩박스 및 그 크기이고, `local_dimensions_m`는 Blender 객체 로컬 경계의 크기입니다. 경사로 폭/길이 등 설계 파라미터는 각 객체의 별도 필드에 있습니다. glTF extras에도 ID와 근거가 들어 있습니다.

## 확인된 명시 치수

전체 8×6.018 m, 좌측 구간 5.018 m, 벽 높이 0.6 m, 우측 복도 폭 1.0 m, 경사로 한쪽 길이 1.1 m, 중앙 높이 0.18 m, 계단 단높이 0.06 m, 디딤판 깊이 0.25 m를 반영했습니다. 경사로 방향 전체 3.2 m와 계단 방향 전체 2.0 m로부터 중앙 평탄부 한 변 1.0 m를 유도했습니다.

계단은 양쪽 각각 0.06 m 및 0.12 m 높이의 두 디딤판이 있으며, 세 번째 0.06 m 단차를 올라 0.18 m 중앙 평탄부에 도달합니다. 경사로 1.1 m는 수평 길이로 해석했습니다. 경사면 실제 길이는 약 1.11463 m, 경사는 약 9.293°입니다.

## 벽 두께 해석

도면에 벽 두께는 없습니다. 기본 벽은 높이 0.6 m의 **양면, 두께 없는 면 메시**입니다. 이 방식으로 도면의 전체 경계 8×6.018 m와 1 m 유효 통로폭을 동시에 보존했습니다. Blender와 GLB의 벽 재질은 양면 표시됩니다.

벽에 임의로 0.04 m 두께를 안쪽으로 부여하면 우측 통로가 0.92 m로 줄고, 바깥쪽으로 부여하면 전체 벽 외곽이 약 8.08×6.098 m로 커집니다. 어느 쪽도 명시되지 않았으므로 이 두께는 적용하지 않았습니다. 실제 두께와 치수 기준이 확인되면 충돌용 솔리드 메시를 별도로 제작해야 합니다.

## 추정 및 제한

- 코너와 회전부, 교차부 중심, ±45° 대각선 방향은 평면도 축척을 기준으로 재구성했습니다
- IN/OUT 약 2×1 m, P 약 1×1 m 및 위치는 평면도에서 추정했습니다
- IN/OUT은 도면의 구역명입니다. 등각도에 보이는 닫힌 외곽벽을 따랐으며 물리적 출입구를 새로 뚫지 않았습니다
- 두 신호등의 도면상 기호 위치는 반영했으나, 실제 기구 크기/높이/방향/표시 상태는 시각화용 추정입니다
- 정지선 위치는 도면의 검정선에 대응하며 폭 0.045 m는 추정입니다
- 슬라럼 영역만 표시했습니다. 콘 개수와 좌표가 없으므로 콘은 만들지 않았습니다
- 재질, 색조, 글자 크기, 바닥판 두께는 시각화 목적입니다
- 3D 객체/치수 검사는 현장 치수, 주행 가능성, 충돌 물리, 센서 또는 로컬라이제이션 검증을 뜻하지 않습니다

추정값별 적용값, 근거, 추후 확인 사항은 `ASSUMPTIONS.md`와 CSV에 있습니다. 먼저 확인할 항목은 벽 두께/치수 기준, 코너 좌표, 출입 개구, 신호등 사양, 콘 배치입니다.

## 객체 분리

객체 ID는 Blender 이름, GLB 노드 이름, JSON ID가 같습니다.

- `floor_*`: 평탄 바닥/중앙 평탄부
- `wall_*`: 외곽과 두 내부 삼각 경계의 벽면
- `ramp_*`: SW/NE 두 경사로
- `stair_*`: NW/SE 두 계단의 개별 디딤판
- `signal_*`: 신호등 기초/기둥/하우징/렌즈
- `marking_*`: 정지선/경사로 및 계단 시작선/주차 테두리
- `label_*`: IN/OUT/P/슬라럼/경사로 글자. 폰트 설치 없이 보이도록 메시 변환
- `zone_*`: IN/OUT/P/슬라럼 영역

카메라와 조명은 `90_Presentation`에 있으며 GLB에는 포함하지 않았습니다. 대시보드나 기존 저장소는 변경하지 않았습니다.

## 재생성

Blender 4.3.2에서 다음 명령을 실행합니다.

```sh
blender -b --threads 8 --python build_arena.py -- --output-dir ./rebuilt
```

모델과 메타데이터만 재생성하려면 `--skip-renders`를 추가합니다. 렌더는 Cycles CPU 96 samples를 사용하며 이 실행 환경에 없는 OpenImageDenoise를 요구하지 않습니다. 한글 라벨의 원본 폰트는 Noto Sans CJK이고, 해당 시스템 폰트가 없는 곳에서 재생성할 경우 폰트 경로를 수정해야 합니다. 배포된 BLEND/GLB의 글자는 이미 메시이므로 폰트가 없어도 보입니다.

```sh
python validate_arena.py
```

이 검사는 파일 일관성과 시각화 데이터 구조만 검사합니다.
